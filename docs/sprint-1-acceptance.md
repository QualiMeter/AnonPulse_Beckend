# AnonPulse — приёмка Sprint 1

## Объём Sprint 1

| User Story | Состояние | Реализация |
|---|---|---|
| US-01 — создание опроса преподавателем | Реализована на backend | Авторизованный пользователь с ролью `teacher` создаёт draft-опрос через `POST /api/polls`. Автор берётся из Identity-сессии. |
| US-02 — несколько вариантов ответа | Реализована на backend | Запрос требует минимум два непустых уникальных варианта. Порядок сохраняется в `Position`, начиная с `0`. |
| US-10 — просмотр статуса опроса | Реализована на backend | `GET /api/polls` и `GET /api/polls/{id}` возвращают только опросы текущего преподавателя и строковый статус `draft`, `open` или `closed`. |
| US-16 — понятные сообщения об ошибках | Реализована на backend | Ошибки валидации возвращаются как `400 application/problem+json` с объектом `errors`; авторизационные ошибки возвращают JSON без HTML redirect. |
| US-20 — информирование об анонимности | Требует реализации на frontend | Текст и критерии приведены ниже. Голосование и пользовательский интерфейс отсутствуют, поэтому история не считается завершённой. |

Публикация, закрытие, голосование, результаты и решения не входят в этот Sprint.

## API для frontend

Все poll-endpoints требуют действительную cookie-сессию и роль `teacher`.

| Метод и маршрут | Назначение | Основные ответы |
|---|---|---|
| `POST /api/auth/login` | Вход по email и паролю | `200`, `400`, `401` |
| `POST /api/auth/logout` | Завершение сессии | `200`, `401` |
| `GET /api/auth/me` | Текущий пользователь и роли | `200`, `401` |
| `POST /api/polls` | Создание draft-опроса | `201`, `400`, `401`, `403` |
| `GET /api/polls` | Список собственных опросов, новые первыми | `200`, `401`, `403` |
| `GET /api/polls/{id}` | Собственный опрос с вариантами | `200`, `401`, `403`, `404` |

Чужой и отсутствующий опрос намеренно дают одинаковый `404`, чтобы не раскрывать наличие чужих данных.

## Примеры

### Вход

```http
POST /api/auth/login
Content-Type: application/json

{
  "email": "teacher@example.com",
  "password": "<password>"
}
```

Успешный ответ устанавливает защищённую `HttpOnly` cookie и возвращает пользователя:

```json
{
  "id": "ab5f5c3d-7f6d-47f4-9c1e-1558b78b4140",
  "email": "teacher@example.com",
  "roles": ["teacher"]
}
```

### Создание опроса

```http
POST /api/polls
Content-Type: application/json
Cookie: __Host-AnonPulse.Auth=<session>

{
  "question": "Какой формат занятий удобнее?",
  "options": [
    "Очный",
    "Дистанционный",
    "Гибридный"
  ]
}
```

Ответ `201 Created` содержит `Location: /api/polls/{id}`:

```json
{
  "id": "b4e786c0-9bc0-45a7-911c-252e55a84c1b",
  "question": "Какой формат занятий удобнее?",
  "status": "draft",
  "createdAt": "2026-10-12T10:00:00Z",
  "publishedAt": null,
  "closedAt": null,
  "options": [
    {
      "id": "c03f4fc2-94cd-496f-89a7-0e27d98e7bd4",
      "text": "Очный",
      "position": 0
    },
    {
      "id": "dac0a65b-12cb-42a2-95a5-8d68cd50ee23",
      "text": "Дистанционный",
      "position": 1
    },
    {
      "id": "43779e77-6253-4d34-9509-3867d76b9e57",
      "text": "Гибридный",
      "position": 2
    }
  ]
}
```

### Ошибка валидации

```http
POST /api/polls
Content-Type: application/json

{
  "question": " ",
  "options": ["Единственный вариант"]
}
```

```json
{
  "title": "One or more validation errors occurred.",
  "status": 400,
  "errors": {
    "Question": ["Question must not be empty."],
    "Options": ["At least two options are required."]
  }
}
```

Вопрос и варианты нормализуются: внешние пробелы удаляются, последовательности пробельных символов заменяются одним пробелом. Дубликаты вариантов сравниваются без учёта регистра. Произвольные ограничения длины в Sprint 1 не вводились.

## Локальная проверка

Требуются .NET SDK 10 и Docker. Docker используется Testcontainers для одноразовых PostgreSQL 17 баз; локальная рабочая или production-база тестами не затрагивается.

```bash
dotnet restore AnonPulse.slnx
dotnet build AnonPulse.slnx --no-restore
dotnet test AnonPulse.slnx --no-build --no-restore
```

Для ручной проверки приложения:

1. Запустить PostgreSQL из `compose.yaml` и настроить `ConnectionStrings:DefaultConnection` через User Secrets.
2. Применить существующую миграцию `InitialCreate` к локальной базе.
3. Задать `DevelopmentTeacher:Email` и `DevelopmentTeacher:Password` через User Secrets.
4. Один раз выполнить development-команду:

   ```bash
   dotnet run --project backend/AnonPulse.Api -- --create-development-teacher
   ```

5. Запустить API обычной командой:

   ```bash
   dotnet run --project backend/AnonPulse.Api
   ```

6. Открыть Scalar, выполнить login и использовать выданную cookie для poll-запросов.

## Сценарий ручной приёмки

1. Без login вызвать `POST /api/polls` и получить `401` в JSON, без redirect на HTML.
2. Войти пользователем без роли `teacher`, повторить запрос и получить `403`.
3. Войти преподавателем и создать опрос с тремя вариантами.
4. Проверить `201`, заголовок `Location`, статус `draft`, UTC-время и позиции `0`, `1`, `2`.
5. Получить опрос через `GET /api/polls/{id}` и убедиться в сохранении порядка.
6. Получить `GET /api/polls` и убедиться, что новые опросы находятся первыми.
7. Войти вторым преподавателем: созданный первым опрос отсутствует в списке, а запрос по его id возвращает `404`.
8. Отправить пустой вопрос, один вариант, пустой вариант и варианты-дубликаты. Для каждого запроса проверить `400 application/problem+json` и отсутствие новых записей в БД.
9. Отправить пустой и повреждённый JSON и получить `400`, а не `500`.

## US-20 — уведомление об анонимности

Предлагаемый текст интерфейса:

> Ответ не сохраняется в таблице голосов вместе с вашим аккаунтом или идентификатором пользователя. Для ограничения повторного голосования может отдельно обрабатываться технический одноразовый идентификатор, не связанный напрямую с записью голоса. При этом абсолютная анонимность не гарантируется: инфраструктурные журналы, сетевые данные и настройки организации могут содержать техническую информацию. Голосование в текущей версии ещё не реализовано.

Критерии реализации для frontend:

- уведомление отображается до отправки голоса и доступно с клавиатуры и экранным диктором;
- текст не скрыт только в tooltip и читаем на мобильном экране;
- интерфейс не утверждает, что анонимность абсолютна;
- после реализации голосования формулировка сверяется с фактическими логами, аналитикой и политикой хранения данных;
- frontend-тест подтверждает отображение уведомления до действия пользователя.

## Security review и технический долг

До публичного использования обязательны следующие работы:

1. **CSRF.** Cookie имеет `SameSite=Strict`, но изменяющие состояние маршруты не используют antiforgery-токен. Нужен согласованный double-submit или ASP.NET Core Antiforgery flow для login, logout и создания опроса. Если потребуется маршрут выдачи токена, его контракт нужно согласовать отдельно.
2. **CORS и topology.** CORS сейчас не настроен. Для отдельного frontend-origin нужен точный allowlist и `AllowCredentials`; wildcard origin недопустим. Необходимо совместно выбрать same-site размещение либо совместимую комбинацию `SameSite`, CORS и CSRF.
3. **HTTPS за reverse proxy.** Cookie всегда `Secure`, включён `UseHttpsRedirection`, но нужно проверить корректную передачу и доверие `X-Forwarded-Proto` на Railway. Иначе приложение может неверно определять исходную схему запроса.
4. **Data Protection Keys.** Ключи не сохраняются во внешнем постоянном хранилище. До нескольких реплик и production-ротаций нужно настроить общее защищённое хранилище ключей; иначе deployment инвалидирует активные cookie-сессии.
5. **Эксплуатационные ограничения.** Не согласованы максимальные длины вопроса и вариантов, ограничение размера request body, pagination и rate limiting. Значения нельзя вводить произвольно: их нужно согласовать и покрыть тестами.

В рамках финализации не добавлялись новые публичные маршруты, CORS-политики или изменения схемы аутентификации.
