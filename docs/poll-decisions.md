# Решения преподавателя по итогам опроса

## Назначение

Решение — опубликованный текст о действиях по итогам обратной связи. Для одного
опроса хранится не более одного актуального решения. История версий в MVP не
ведётся.

## Права доступа

- создать или обновить решение может преподаватель-владелец опроса;
- пользователь с ролью `admin` может создать или обновить решение любого опроса;
- другой преподаватель получает `404`, чтобы не раскрывать чужой опрос;
- анонимный пользователь получает `401`, пользователь без разрешённой роли —
  `403`;
- публичный GET не требует Identity-сессии.

## Создание и обновление

```http
PUT /api/polls/{pollId}/decision
Content-Type: application/json

{
  "text": "Со следующей недели материалы лекций будут доступны заранее."
}
```

Успешный ответ:

```json
{
  "id": "11111111-1111-1111-1111-111111111111",
  "pollId": "22222222-2222-2222-2222-222222222222",
  "text": "Со следующей недели материалы лекций будут доступны заранее.",
  "publishedAt": "2026-10-13T12:00:00Z"
}
```

Первый PUT создаёт строку `decisions`; последующие обновляют её, сохраняя ID и
первоначальный `AuthorId`. Автор определяется только из Identity-сессии и не
принимается из JSON.

`PublishedAt` — UTC-время публикации текущей версии текста. Оно меняется при
создании, изменении текста или публикации ранее неопубликованной строки. Повторный
PUT того же текста (после удаления крайних пробелов) не меняет `PublishedAt` и не
выполняет лишнюю запись.

Внутренние пробелы и переводы строк сохраняются. Текст возвращается как JSON-
строка и не интерпретируется backend как HTML. Frontend должен отображать его как
текст, не через небезопасную HTML-вставку.

Решение разрешено для `open` и `closed`. Для `draft` возвращается
`409 application/problem+json`.

Ограничение MVP: после удаления крайних пробелов текст должен содержать от 1 до
5000 символов.

Ошибки PUT:

- `400 application/problem+json` — пустой текст или более 5000 символов;
- `401 application/problem+json` — нет действующей сессии;
- `403 application/problem+json` — нет роли `teacher` или `admin`;
- `404 application/problem+json` — опрос не найден или не принадлежит
  преподавателю;
- `409 application/problem+json` — опрос остаётся черновиком.

## Публичное чтение

```http
GET /api/polls/{pollId}/decision
```

Ответ содержит только `id`, `pollId`, `text` и `publishedAt`. Email, автор,
Identity claims, cookie и другие персональные данные не возвращаются. Ответ имеет
`Cache-Control: no-store`.

Для отсутствующего опроса, отсутствующего решения, черновика или строки с
`publishedAt = null` возвращается одинаковый `404 application/problem+json`.
Так содержимое черновиков и неопубликованных записей не раскрывается.

## Конкурентность и схема данных

PUT выполняется в транзакции и блокирует строку опроса через
`SELECT ... FOR UPDATE`. Два одновременных запроса сериализуются, поэтому второй
увидит решение первого и обновит ту же строку. Существующий уникальный индекс
`ux_decisions_poll_id` остаётся дополнительной гарантией одного решения на опрос.

Существующая таблица `decisions` достаточна; новая миграция не требуется.

## CSRF и ограничения MVP

Cookie Identity имеет `HttpOnly`, `Secure` и `SameSite=Strict`; глобальный CORS
не открыт. PUT рассчитан на same-site frontend с cookie credentials. Отдельный
anti-forgery token в текущем API отсутствует, поэтому до перехода на cross-site
frontend или ослабления `SameSite` требуется согласовать origin-проверку либо
anti-forgery контракт. Текущие настройки безопасности этим PR не ослабляются.

Не входят в MVP: история версий, комментарии, уведомления, rich text/HTML,
экспорт, подтверждение прочтения и отдельный административный интерфейс.
