# Агрегированные результаты опросов

## Область функции

US-09 и US-11 реализованы read-only endpoint:

```http
GET /api/polls/{pollId}/results
```

Доступ зависит от статуса опроса. Содержимое черновика через этот маршрут не
раскрывается:

- `open` — `200`, промежуточные результаты (`resultsType: "interim"`) только
  преподавателю-владельцу и администратору;
- `open` без Identity-сессии — `401 application/problem+json`;
- `open` для другого преподавателя — `404 application/problem+json`, чтобы не
  раскрывать чужой опрос;
- `open` для пользователя без роли `teacher` или `admin` —
  `403 application/problem+json`;
- `closed` — публичный `200`, итоговые результаты (`resultsType: "final"`), в
  том числе без Identity-сессии;
- `draft` — `409 application/problem+json`;
- неизвестный ID — `404 application/problem+json`.

Ответы имеют `Cache-Control: no-store`, чтобы frontend не показывал устаревший
снимок промежуточных результатов.

## Формат ответа

```json
{
  "id": "11111111-1111-1111-1111-111111111111",
  "status": "open",
  "resultsType": "interim",
  "totalParticipants": 3,
  "questions": [
    {
      "id": "22222222-2222-2222-2222-222222222222",
      "text": "Материал понятен?",
      "position": 0,
      "options": [
        {
          "id": "33333333-3333-3333-3333-333333333333",
          "text": "Да",
          "position": 0,
          "voteCount": 2,
          "percentage": 66.67
        },
        {
          "id": "44444444-4444-4444-4444-444444444444",
          "text": "Нет",
          "position": 1,
          "voteCount": 1,
          "percentage": 33.33
        }
      ]
    }
  ]
}
```

Вопросы и варианты сортируются по сохранённой позиции. `totalParticipants`
считается по `vote_participations` конкретного опроса и не суммируется между
вопросами. Количество голосов агрегируется по вариантам отдельно для каждого
вопроса.

Процент рассчитывается как
`voteCount / totalQuestionVotes * 100` и округляется до двух знаков по правилу
`AwayFromZero`. Если у вопроса нет голосов, все проценты равны `0`.

## Согласованность и приватность

Все запросы одного ответа выполняются в PostgreSQL-транзакции с изоляцией
`REPEATABLE READ`. Проверка статуса и владельца выполняется в том же снимке до
агрегации. Статус, число участников, структура опроса и сгруппированные голоса
поэтому относятся к одному согласованному снимку, даже если параллельно идёт
голосование или закрытие опроса.

Голоса агрегируются одним SQL `GROUP BY` по `option_id`; отдельных запросов для
каждого варианта нет. Endpoint не возвращает пользователей, email, исходные
голоса, времена, cookie, `token_hash` или записи участия.

## Ограничения

- Проценты рассчитываются независимо для каждого вопроса.
- Сумма округлённых процентов иногда может отличаться от `100.00` на одну сотую.
- API не строит графики, временные ряды, экспорт или расширенную аналитику.
- Публичность относится только к итоговым агрегатам закрытых опросов.
- Frontend не должен запрашивать или показывать промежуточные результаты
  студентам. Для запроса промежуточных результатов преподавательский frontend
  передаёт Identity cookie обычным same-site запросом.
- Схема PostgreSQL не меняется; новая EF Core migration не требуется.
